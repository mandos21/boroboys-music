# Application Overview

## Goals
- Collect monthly song submissions from registered users
- Assemble Spotify playlist each month with admin curation tools
- Persist rich track metadata for analytics and Last.fm insights
- Expose a REST API that powers the React frontend for browsing, submitting, and managing playlists

## High-Level Architecture
- **Frontend**: React/Vite single-page application consuming the REST API
- **Backend**: FastAPI application exposing Spotify/Last.fm/Postgres functionality via versioned REST routes and services
- **Data Layer**: SQLAlchemy ORM with Alembic migrations targeting PostgreSQL
- **Integrations**:
  - Spotify Web API via `spotipy`
  - Last.fm API via `pylast`
- **Task Orchestration**: Lightweight background jobs scheduled via APScheduler for monthly playlist finalization

## Core Components
- `app/config.py`: settings management via pydantic reflecting environment variables (DB parts, Spotify keys, Last.fm creds, DB URL composer)
- `app/db/`:
  - `models.py`: SQLAlchemy models
  - `session.py`: session factory and engine helpers (`build_postgres_url`)
  - `crud.py`: data access helpers (Spotify OAuth upsert, playlist utilities)
- `app/auth/spotify_auth.py`: Spotify OAuth helpers for login and token refresh
- `app/services/`:
  - `spotify_service.py`: wrappers for playlist, track metadata, and user scopes
  - `lastfm_service.py`: wrappers for user listening stats
  - `playlist_manager.py`: monthly playlist orchestration logic
- `app/main.py`: FastAPI application factory and middleware setup
- `app/api/`: versioned routers, dependencies, and request/response schemas backing the frontend
- `app/schemas.py`: Pydantic DTOs bridging UI and service layer
- `app/tasks.py`: scheduled job entry points for monthly finalization and sync jobs
- `app/bootstrap.py`: helper utilities used by the setup wizard to persist config, initialize the DB, and seed an admin user
- `tests/`: pytest suite with fixtures for DB and API client mocks

## Data Model (initial)
- `users` (id, username, display_name, role, email, password_hash, spotify_user_id, spotify_access_token, spotify_refresh_token, spotify_token_expires_at, spotify_scope, lastfm_username, created_at)
- `tracks` (id, spotify_track_id, name, artist, album, duration_ms, release_date, spotify_url, genres JSON, lastfm_tags JSON, added_at)
- `submissions` (id, user_id, track_id, submission_month, notes, is_locked, created_at, updated_at)
- `playlists` (id, name, description, month, spotify_playlist_id, created_at, updated_at, finalized_by)
- `playlist_tracks` (playlist_id, track_id, position)
- `listening_stats` (id, user_id, track_id, lastfm_playcount, lastfm_last_listened_at, snapshot_at)

## Bootstrapping & Operations
- First run: start the FastAPI app and call the `/api/v1/setup/*` endpoints to unlock the installer, capture environment credentials, and seed the first admin user. The wizard writes `.env` and initializes the database schema.
- Users authenticate via Spotify OAuth; tokens and profiles are persisted for reuse and automatic refresh.

## Key User Flows
1. **User Submission**: user authenticates with Spotify, searches for a track, and the app stores/upserts track info + submission row (editable until playlist finalizes)
2. **Playlist Finalization**: scheduler (or manual admin action) locks submissions for month, creates Spotify playlist with user tokens, persists playlist entries, notifies users
3. **History Browsing**: React UI pulls playlist history through `/api/v1/playlists`
4. **Song Lookup**: search across `tracks` and `submissions` via `/api/v1/tracks/search`
5. **Analytics**: display Last.fm stats aggregated per user/track and monthly summary

## Security & Auth Considerations
- Spotify OAuth is the primary authentication mechanism; access/refresh tokens are stored encrypted-at-rest (future work) and refreshed automatically
- Session cookies managed by Starlette middleware; logout clears the server-side session
- Admin actions gated via `user.role`

## Configuration & Secrets
- `.env` file managed via `python-dotenv` for local dev (generated by the setup wizard); the committed file is a sanitized template.
- Environment variables required:
  - `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`
  - `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REDIRECT_URI`, `SPOTIFY_SCOPE`
  - `LASTFM_API_KEY`, `LASTFM_SHARED_SECRET`
  - `SECRET_KEY` for session/auth
